# Chapter 9: Running in CI

Tests that only run on your laptop aren't tests — they're demos. This chapter covers everything needed to run your Vibium test suite in GitHub Actions: headless mode, exit codes, environment variables, and a working workflow file.

---

## 9.1 headless: true in CI

When there's no screen, there's no visible browser window. CI runners don't have a display server by default, so `headless: false` fails. Always use `headless: true` in CI:

```typescript
const browser = await vibium.start({ headless: true })
```

During development you might want `headless: false` to watch what's happening. Use an environment variable to switch:

```typescript
const headless = process.env.CI === 'true'
const browser = await vibium.start({ headless })
```

GitHub Actions sets `CI=true` automatically. Locally it's unset, so `headless` defaults to `false`.

---

## 9.2 Exit Codes

A test script must exit with code 1 when tests fail, or CI won't know the job failed. This is why every standalone script in this course ends with:

```typescript
main().catch(err => {
  console.error('Test failed:', err.message)
  process.exit(1)
})
```

With Vitest, exit codes are handled automatically — a failing test causes `vitest run` to exit with code 1. You don't need to manage this manually.

## 9.3 The Vibium Daemon in CI

The Vibium CLI requires a running daemon (`vibium daemon start`). In CI you need to start it in your workflow before running tests, and stop it after:

```yaml
- name: Start Vibium daemon
  run: vibium daemon start

- name: Run tests
  run: npm test

- name: Stop Vibium daemon
  if: always()
  run: vibium daemon stop
```

The `if: always()` on the stop step ensures the daemon is stopped even if tests fail.

## 9.4 The GitHub Actions Workflow

A complete workflow file at `.github/workflows/tests.yml`:

```yaml
name: Tests

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Install Vibium
        run: npm install -g vibium

      - name: Start Vibium daemon
        run: vibium daemon start

      - name: Run tests
        run: npm test
        env:
          CI: true
          AUT_BASE_URL: ${{ vars.AUT_BASE_URL }}

      - name: Stop Vibium daemon
        if: always()
        run: vibium daemon stop
```

## 9.5 Environment Variables

Hard-coding URLs in test code means a different environment (staging, preview) requires code changes. Use environment variables instead:

```typescript
const AUT = process.env.AUT_BASE_URL ?? 'https://automation-exercise.daisyladybug.com'
```

In CI, set `AUT_BASE_URL` as a GitHub Actions variable (`vars.AUT_BASE_URL`) or secret (`secrets.AUT_BASE_URL`). Locally, set it in a `.env` file (add `.env` to `.gitignore`) or in your shell.

For secrets (API keys, passwords), always use `secrets.*` in GitHub Actions — never `vars.*`:

```yaml
env:
  API_KEY: ${{ secrets.API_KEY }}
```

## 9.6 A CI-Ready Test Script

Update your Vitest config to read the timeout from env so CI can override it:

```typescript
// vitest.config.ts
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    globals: false,
    testTimeout: Number(process.env.TEST_TIMEOUT ?? 60_000),
    hookTimeout: 30_000,
  }
})
```

And your `package.json` test script:

```json
"scripts": {
  "test": "vitest run",
  "test:ci": "vitest run --reporter=verbose"
}
```

The `--reporter=verbose` flag prints each test result, which is more useful than the compact output in CI logs.
