Chapter 4

Working with Forms

Fill text inputs, drive select dropdowns, assert validation errors, and write a complete form test covering both the product search and the checkout flow.

Hands-on TypeScript ~25 min
4.1

The Forms We'll Work With

In Chapter 3 you wrote a test that reads and asserts on a page. Now we're going to interact with it. Forms are where the majority of real-world test automation work happens — search fields, dropdowns, checkouts, registration flows. Let's start by mapping out what we're working with. The app has forms in two places:

/products — Search & Filter
  • textSearch products...
  • selectCategory: All / Electronics / Apparel / Home / Books
  • selectSort: Popular / Price ↑ / Price ↓
/checkout — Order Form
  • textfirstName, lastName
  • emailemail
  • telphone
  • textaddress, city, state, zipCode
  • textcardName, cardNumber, cardExpiry, cardCvc
  • submitPlace Order

The checkout form validates all required fields. Submitting empty shows messages like ✗ First name required and ✗ Valid email required.

4.2

Filling Text Inputs

The method for filling a text input is element.fill(text). It clears whatever is in the field first, then types the new value. The search input has a placeholder of "Search products..." — we can use that as a CSS attribute selector to target it precisely. After filling, the product list filters in real time:

ch04/01-search-filter.ts (excerpt)
await page.go(`${AUT}/products`)

const search = await page.find("input[placeholder='Search products...']")
await search.fill('headphones')

const result = await page.find({ text: 'Wireless Headphones' })
assert.ok(await result.isVisible(), 'search result visible')

const other = await page.find({ text: 'Premium T-Shirt' })
assert.ok(!await other.isVisible(), 'unrelated product hidden')

fill() vs type(): fill() clears the field first, then types the new value. Use type() if you need to append without clearing.

4.3

Working with Select Dropdowns

The category and sort dropdowns are standard <select> elements. Call element.selectOption() with the visible option text.

select dropdowns
// filter by category
const category = await page.find('select:first-of-type')
await category.selectOption('Electronics')

const label = await page.find({ text: 'Electronics' })
assert.ok(await label.isVisible(), 'Electronics filter active')

// change sort order
const sort = await page.find('select:last-of-type')
await sort.selectOption('Price: Low to High')
4.4

Filling the Checkout Form

All checkout inputs have name attributes, making them easy to target precisely. Locate each by input[name=...] and fill it. After filling, verify a field's value with element.value().

fill checkout fields
const fieldMap: Record<string, string> = {
  firstName:  'Jane',
  lastName:   'Smith',
  email:      'jane@test.com',
  phone:      '5551234567',
  address:    '456 Oak Ave',
  city:       'Portland',
  state:      'OR',
  zipCode:    '97201',
  cardName:   'Jane Smith',
  cardNumber: '4111111111111111',
  cardExpiry: '12/26',
  cardCvc:    '999',
}

for (const [name, value] of Object.entries(fieldMap)) {
  const field = await page.find(`input[name=${name}]`)
  await field.fill(value)
}

// verify a field after filling
const emailField = await page.find('input[name=email]')
assert.equal(await emailField.value(), 'jane@test.com', 'email field value')

The fieldMap loop is a clean pattern for forms with many fields: define the data separately, keep the fill logic generic. Swapping in different test data later means only changing the object.

4.5

Asserting Validation Errors

Before we test the happy path, let's test what happens when things go wrong. Submitting an empty form should show validation errors for every required field. Testing this matters — a form that accepts empty data is a bug. And notice: this validation test and the happy-path checkout test are separate tests. Each is atomic — it does one thing, sets up its own state, and doesn't depend on the other. If we combined them, a failure in validation would prevent checkout from being tested at all.

✗ First name required
✗ Last name required
✗ Valid email required
✗ Valid phone required
✗ Address required
✗ City required
✗ State required
✗ Valid ZIP required
✗ Cardholder name required
✗ Valid card number required
✗ Format MM/YY
✗ Valid CVC required
ch04/02-validation-errors.ts (excerpt)
const submit = await page.find({ role: 'button', text: 'Place Order' })
await submit.click()

const errors = [
  '✗ First name required',
  '✗ Last name required',
  '✗ Valid email required',
  // ... all 12 messages
]

for (const message of errors) {
  const el = await page.find({ text: message })
  assert.ok(await el.isVisible(), `error visible: ${message}`)
}
4.6

A Complete Form Test

Here's the full checkout flow: add a product, navigate to checkout, fill all 12 fields using the fieldMap loop, submit, and assert we land on the confirmation URL. The cart must have items before the checkout form renders — we navigate to a product and click "Add to Cart" first. This is an integration test: it tests a real end-to-end user flow, touches multiple pages, and is still atomic — it sets up its own cart state and doesn't depend on any prior test.

ch04/03-checkout-flow.ts
// 1. search filter
await page.go(`${AUT}/products`)
const search = await page.find("input[placeholder='Search products...']")
await search.fill('headphones')
assert.ok(await (await page.find({ text: 'Wireless Headphones' })).isVisible())

// 2. category filter
const category = await page.find('select:first-of-type')
await category.selectOption('Electronics')

// 3. add to cart
await page.go(`${AUT}/products/prod_001`)
const addToCart = await page.find({ role: 'button', text: 'Add to Cart' })
await addToCart.click()

// 4. fill checkout form
await page.go(`${AUT}/checkout`)
for (const [name, value] of Object.entries(fieldMap)) {
  const field = await page.find(`input[name=${name}]`)
  await field.fill(value)
}

// 5. submit and assert confirmation
const submit = await page.find({ role: 'button', text: 'Place Order' })
await submit.click()
await page._waitForURL('**/confirmation')

Exercise & Quiz

Exercise

Search + Checkout + Validation

Write a test called testSearchAndCheckout that:

  1. Navigates to /products and searches for 'yoga'
  2. Asserts that 'Yoga Mat' is visible and 'Wireless Headphones' is not visible
  3. Navigates to '/products/prod_007' and adds it to the cart
  4. Navigates to /checkout
  5. Fills all 12 checkout fields using the fieldMap loop pattern with your own data
  6. Clicks "Place Order" and waits for _waitForURL('**/confirmation')
  7. Asserts that the current URL includes '/confirmation'

Then write a second test called testValidationErrors (separate function, separate browser) that adds a product, navigates to checkout, clicks "Place Order" without filling anything, and asserts at least three validation error messages are visible.
