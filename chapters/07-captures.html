Chapter 7

Capturing Events

Flip the direction: instead of sending actions to the browser, listen for events it sends back. Intercept native dialogs, collect console messages, and save downloaded files.

Intermediate TypeScript ~20 min
7.1

The Capture Pattern

Every chapter so far has been about sending commands to the browser. In this chapter we flip the direction — instead of telling the browser what to do, we listen for events the browser fires at us. All three captures share the same API shape: set up the listener before the action that triggers the event, then trigger the action — both inside Promise.all. If you try to await the capture first and then click, you deadlock. Captures are subscriptions — you must subscribe before the event fires.

capture.dialog()
Intercepts native alert / confirm / prompt. Returns dialog type and message.
capture.console()
Collects console messages during an action. Returns array of {type, text}.
capture.download()
Intercepts file downloads. Saves file and returns suggestedFilename.

Critical: If you await capture.dialog() first, then click, you deadlock. The capture waits for the dialog, the dialog waits for the click. Use Promise.all so both start concurrently.

7.2

Capturing Dialogs

page.capture.dialog(action) intercepts the next native browser dialog and handles it automatically — pass 'accept' or 'dismiss'. Our AUT uses React-rendered modals, not native dialogs, so we use page.setContent() to inject a minimal HTML page with real native dialogs for this example:

ch07/01-dialog.ts (excerpt)
// set up inline page with alert and confirm
await page.setContent(`
  <button onclick="alert('Hello!')">Show Alert</button>
  <button onclick="confirm('Delete?')">Show Confirm</button>
`)

// capture the alert — fire-and-forget inside Promise.all
const [result] = await Promise.all([
  page.capture.dialog('accept'),
  (async () => {
    const btn = await page.find({ role: 'button', text: 'Show Alert' })
    btn.click()  // no await — intentional
  })(),
])

assert.equal(result.type, 'alert')
assert.equal(result.message, 'Hello!')

Why fire-and-forget? click() waits for the browser to settle after the click. A dialog blocks the browser from settling — so awaiting click + awaiting capture deadlocks. Firing the click without awaiting lets the dialog appear, the capture handles it, and Promise.all resolves.

7.3

Capturing Console Messages

page.capture.console() collects all console output emitted during a block of browser actions. Use this to verify your app logs the right messages in response to user actions — or, just as importantly, that it doesn't log errors it shouldn't. Each message in the returned array has a type matching the console method ('log', 'warning', 'error') and a text property.

ch07/02-console.ts (excerpt)
const [messages] = await Promise.all([
  page.capture.console(),
  (async () => {
    const btn = await page.find({ role: 'button', text: 'Add Item' })
    btn.click()
  })(),
])

const logs = messages.filter((m: any) => m.type === 'log')
const warns = messages.filter((m: any) => m.type === 'warning')

assert.equal(logs[0].text, 'item added')
assert.ok(warns[0].text.includes('stock low'))
7.4

Capturing Downloads

page.capture.download(dir) intercepts a file download triggered by a link or button click. Pass a directory where the file should be saved. The same Promise.all pattern applies — register the capture before triggering the download, fire the click without awaiting. The download descriptor has suggestedFilename and a path to the saved file.

ch07/03-download.ts (excerpt)
const [download] = await Promise.all([
  page.capture.download(downloadDir),
  (async () => {
    const link = await page.find({ role: 'link', text: 'Download CSV' })
    link.click()
  })(),
])

assert.equal(download.suggestedFilename, 'products.csv')
assert.ok(fs.existsSync(path.join(downloadDir, download.suggestedFilename)))

Exercise & Quiz

Exercise

Three Capture Tests

Write three separate test functions, one for each capture type. Each must use Promise.all with a fire-and-forget click inside the second argument.

  1. testDeleteConfirmation — use page.capture.dialog('dismiss') to cancel a delete confirmation; assert result.type is 'confirm' or 'alert'; assert the item is still in the cart after dismissing
  2. testConsoleErrors — navigate to a page, use page.capture.console(), perform any interaction, assert messages is an array (even if empty)
  3. testDownload — navigate to a page with a CSV download link, use page.capture.download('/tmp/vibium-downloads'), click the trigger, assert download.suggestedFilename ends with '.csv'
Quiz

5 Questions

1. Why must the click inside a Promise.all capture be fire-and-forget?

  • A. await inside Promise.all is a syntax error
  • B. Awaiting the click would block until the dialog is handled, creating a deadlock — the capture promise can't resolve because the click never completes
  • C. Fire-and-forget clicks run faster than awaited clicks
  • D. The Vibium API requires it for dialog captures only

2. page.capture.dialog('accept') vs page.capture.dialog('dismiss') — what is the difference?

  • A. accept clicks OK; dismiss clicks Cancel or closes the dialog
  • B. accept intercepts only alerts; dismiss intercepts only confirms
  • C. They are identical — both close the dialog
  • D. dismiss is for file dialogs; accept is for browser alerts

3. The result from page.capture.dialog() contains:

  • A. The HTML of the page after the dialog closed
  • B. The button text that was clicked
  • C. The dialog type and message text
  • D. Whether the user accepted or dismissed

4. Console captures collect:

  • A. Only console.error calls
  • B. Only console.log calls from your test code
  • C. All browser console messages — log, warn, error, info — that fire while the capture is active
  • D. Only messages that occur before the trigger click

5. What does download.suggestedFilename contain?

  • A. The full path to the file on disk
  • B. The MIME type of the downloaded file
  • C. The filename the browser assigned to the download, as it would appear in the download bar
  • D. The URL of the file that was downloaded
