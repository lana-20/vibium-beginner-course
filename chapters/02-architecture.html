Chapter 2

How Vibium Works —
Architecture Overview

The engine, the three interfaces, the Browser → Context → Page → Element hierarchy, finding elements, and the three interaction modes that underpin every test you'll write.

TypeScript examples Concepts ~15 min
2.1

The Engine and the Interfaces

At its core, Vibium is a single automation engine with three different ways to interact with it.

CLI
Standalone binary. One command at a time from the terminal. Great for exploration.
MCP Server
Implements the Model Context Protocol. AI agents drive the browser without any glue code.
Client Libraries
TypeScript, Python, Java. Full programmatic API. This is how tests are written.
↑ all three talk to the same underlying engine ↑

All three interfaces result in the same browser actions. Skills you develop writing TypeScript tests transfer directly if you later work with the CLI or with an AI agent using MCP.

2.2

How a Test Actually Runs

When you call vibium.start(), Vibium launches a browser process, opens a browser context (a fresh browser profile), and creates a page (a browser tab). Your TypeScript code talks to that page through Vibium's API.

The browser runs in two modes. Headed mode opens a visible window — use this while writing and debugging tests. Headless mode runs the browser invisibly — use this in CI pipelines where there is no display.

2.3

The Object Hierarchy

Vibium organizes browser automation around four levels:

1 Browser The browser process. One per test run. Start it, use it, close it.
2 BrowserContext Isolated session — own cookies, storage, auth state. Contexts run in parallel without interfering.
3 Page A single browser tab. Most tests work with one page at a time.
4 Element A DOM node: button, input, heading, link. Click it, read it, fill it.
ch02/browser-hierarchy.ts
import vibium from 'vibium'

const browser = await vibium.start({ headless: false })
const context = await browser.newContext()
const page    = await context.newPage()

await page.go('https://automation-exercise.daisyladybug.com/')

const button = await page.find({ role: 'link', text: 'Explore Products' })
await button.click()

await browser.close()
2.4

Finding Elements

Vibium's primary locator is page.find(). The most reliable form is role + text — it describes what the element is and what it says, staying stable even as HTML structure changes.

find strategies
// role + text — most robust, use for interactive elements
const btn = await page.find({ role: 'button', text: 'Add to cart' })

// CSS selector — use when role+text isn't enough
const input = await page.find({ css: '#search-input' })

// text only — fine for reading content, returns outermost match
const heading = await page.find({ text: 'Featured Products' })

Important: find({ text }) matches DOM text, not rendered text. CSS text-transform is never applied. If the DOM says "add to cart" but the page renders "ADD TO CART", search for "add to cart".

2.5

Actions, Captures, and Waits

Three categories of operations. Understanding the distinction makes the whole API easier to navigate.

Actions — things you do: navigate, click, fill, scroll. Captures — listeners for async browser events: dialogs, console output, downloads. Waits — blocks until a condition is true: URL changed, text appeared, element visible.

captures — the key pattern
// Register the capture BEFORE triggering the action, always.
const [dialog] = await Promise.all([
  page.capture.dialog(),   // listener registered first
  button.click()            // action fires second
])

console.log(dialog.message)
await dialog.accept()
waits
await page.waitForURL('**/checkout/success')
await page.waitForText('Order confirmed')
2.6

Network Layer

Vibium lets you intercept browser requests and fulfill them with mock responses, modify them, or block them. You won't need this in the early chapters — we'll work with the real app throughout. But it's worth knowing the feature exists for when tests become flaky because of an unstable external API.

network interception
await page.route('**/api/products', route => {
  route.fulfill({ status: 200, body: JSON.stringify({ products: [] }) })
})
