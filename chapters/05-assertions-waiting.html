Chapter 5

Assertions and Waiting

Master element state methods, synchronize with async DOM updates using page.find({ text }) and page._waitForURL(), and write a test that verifies live cart totals after a quantity change.

Intermediate TypeScript ~20 min
5.1

Why Waiting Matters

Here's the thing about browser automation that trips up almost everyone at first: the browser is asynchronous. After you click a button, the app might update the DOM in the same frame, or it might need to process a state update, run a reducer, re-render a React component, and then update the DOM. If your assertion runs before the update lands, it fails — not because the feature is broken, but because your test was faster than the page. This is a race condition, and race conditions are the worst kind of test failures — they erode trust in your test suite.

Race condition
await button.click()
// may assert before DOM updates
const total = await page.find(
  { text: '$159.98' }
)
assert.ok(await total.isVisible())
Correct pattern
await button.click()
const total = await page.find(
  { text: '$159.98' }
)
assert.ok(await total.isVisible())

Vibium's actions (click, fill, selectOption) auto-wait for the target to be interactive. But state that appears after an action — new text in the DOM, a new URL — needs an explicit page.find({ text }) or page._waitForURL() call before you assert. page.find({ text }) polls until that string appears anywhere on the page. Once it does, you know the DOM has settled and your assertion is safe.

5.2

Element State Methods

Once you have an element from page.find(), six state methods are available. Let me walk through each one and when to reach for it:

isVisible()
Is it rendered on screen? Returns boolean.
isEnabled()
Is it interactive? False when disabled attribute set.
isChecked()
For checkboxes and radio buttons.
text()
The element's visible text content.
value()
Current value of an input field.
attr('name')
Value of any HTML attribute, e.g. href.
ch05/01-element-state.ts (excerpt)
const price = await page.find({ text: '$79.99' })
assert.ok(await price.isVisible(), 'price visible')

const addToCart = await page.find({ role: 'button', text: 'Add to Cart' })
assert.ok(await addToCart.isEnabled(), 'Add to Cart enabled')

const link = await page.find({ role: 'link', text: 'Products' })
const href = await link.attr('href')
assert.ok(href?.includes('/products'), 'nav link href')
5.3

Waiting for Text and URL Changes

page.find({ text }) polls until an element with that text exists on the page — use it after any action that causes a DOM update. page._waitForURL(pattern) blocks until the URL matches a glob pattern. Both default to a 30-second timeout.

ch05/02-waits.ts (excerpt)
const category = await page.find('select:first-of-type')
await category.selectOption('Electronics')

// find polls until the label appears — no separate wait needed
const label = await page.find({ text: 'Showing 3 of 12 products' })
assert.ok(await label.isVisible(), 'filter label updated')

// navigate then wait for URL
const link = await page.find({ role: 'link', text: 'Wireless Headphones' })
await link.click()
await page._waitForURL('**/products/prod_001')
5.4

Asserting on Counts and Attributes

Use (await page.findAll(selector)).length to assert element counts. Use element.attr(name) to assert attribute values.

count + attribute assertions
await page.go(`${AUT}/products`)
const count = (await page.findAll('a[href*="/products/prod_"]')).length
assert.equal(count, 12, '12 products on catalog page')

const link = await page.find({ role: 'link', text: 'Products' })
const href = await link.attr('href')
assert.ok(href?.includes('/products'), 'nav link points to products')
5.5

A Complete State Test

This test adds Wireless Headphones to the cart, increases the quantity to 2, and asserts that three separate DOM values update correctly. We call page.find({ text }) twice after the click — once for the count label and once for the subtotal — because the DOM updates for each value may not happen in the same render cycle. Don't assert until you've confirmed the page has settled on the specific values you're checking.

ch05/03-cart-totals.ts
// add Wireless Headphones ($79.99) to cart
await page.go(`${AUT}/products/prod_001`)
const addToCart = await page.find({ role: 'button', text: 'Add to Cart' })
await addToCart.click()
await page.go(`${AUT}/cart`)

// verify initial state: qty 1
assert.ok(
  await (await page.find({ text: '1 item · 1 product' })).isVisible()
)

// increase quantity
const increase = await page.find({
  role: 'button',
  text: 'Increase Wireless Headphones quantity'
})
await increase.click()

// find polls — waits for React re-render automatically
await page.find({ text: '2 items · 1 product' })
await page.find({ text: '$159.98' })

assert.ok(await (await page.find({ text: '$159.98' })).isVisible(), 'subtotal')
assert.ok(await (await page.find({ text: '$175.98' })).isVisible(), 'total')

Why two find({ text }) calls? The subtotal and total are computed separately. Polling for the subtotal doesn't guarantee the total has updated too — poll for each value you intend to assert.
